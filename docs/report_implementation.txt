Реализация серверной части

Структура серверной части приложения отображена на диаграмме компонентов (см. рисунок X).

<РИСУНОК: components.puml>

Проект делится на три логических пакета: motoshop (конфигурация), shop (бизнес-логика) и templates (шаблоны представления).

Пакет motoshop содержит общие настройки проекта. Компонент settings.py описывает параметры подключения к базе данных, набор установленных приложений, список middleware, настройки аутентификации и сессий. Компонент urls.py выполняет роль корневого маршрутизатора: он принимает все входящие запросы и делегирует их обработчикам приложения shop.

Пакет shop реализует всю прикладную логику магазина. Компонент urls.py задаёт конкретные URL-маршруты и связывает их с соответствующими представлениями. Компонент views.py содержит функции-представления, которые принимают запрос, обращаются к моделям для получения данных, валидируют пользовательский ввод через формы, работают с корзиной и возвращают сформированный HTML-ответ. Компонент models.py описывает структуру данных предметной области: товары и их подклассы (мотоциклы, экипировка, запчасти и прочее), заказы, пользователи, отзывы. Компонент forms.py содержит формы ввода (регистрация, вход, оформление заказа, отзыв) с правилами валидации. Компонент cart.py инкапсулирует логику сессионной корзины, не требующей сохранения в базе данных. Компонент auth_backends.py реализует нестандартный способ аутентификации - по email вместо имени пользователя. Компонент admin.py регистрирует модели в административной панели и настраивает её отображение. Компонент context_processors.py предоставляет шаблонам общие данные (в частности, счётчик корзины), доступные на любой странице без ручного проброса из каждого представления.

Пакет templates содержит HTML-шаблоны. Базовый шаблон base.html определяет общий каркас страницы (шапка, подвал, подключение стилей и скриптов). Файлы из templates/shop/ наследуют этот каркас и описывают конкретные страницы - каталог, карточку товара, корзину, оформление заказа, личный кабинет.

Связи на диаграмме отражают направления использования. Корневой маршрутизатор motoshop/urls.py подключает shop/urls.py, а тот, в свою очередь, вызывает нужное представление. Представление обращается к формам, моделям и корзине, после чего передаёт данные в соответствующий шаблон. Шаблоны страниц расширяют базовый шаблон. Отдельно показаны административный модуль и модуль аутентификации, которые работают с моделью пользователя и остальными моделями напрямую, минуя слой представлений.
